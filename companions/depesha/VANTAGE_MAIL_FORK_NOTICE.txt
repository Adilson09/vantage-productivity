# Vantage Mail

This companion is a Vantage Productivity fork of [Depesha](https://github.com/fgbm/depesha), version 0.8.17, upstream commit `d3c3a2b63cc9a1e194aa3ed3842d8d3fd0f2e0b4`. Vantage modifications name the companion `Vantage Mail` (`vantage-mail.exe`) and disable independent updates. The existing `org.asteroffice.mail` application and credential identities are retained for connected-account continuity. `VANTAGE_MAIL_PROFILE` selects an optional absolute profile directory; `ASTER_MAIL_PROFILE` remains supported as a legacy fallback. Both `vantage-mail` and legacy `aster-mail` links are accepted. Existing signed notification links retain their original format. The override contains separate `config`, `data`, `cache`, `logs`, and `webview` subdirectories, with profile-specific hashed process and credential identities. Each explicit profile retains single-instance protection without activating a different profile. An invalid override stops startup instead of falling back to a normal profile. Existing Depesha accounts, queued mail, browser data and credentials are not imported automatically.

The companion's mail functions contact the servers for accounts the user explicitly adds. A new profile starts with no accounts. Verification must use a new empty profile and must not add accounts, retrieve mail, send messages, access credentials, or run the upstream mail-server E2E scenarios against real mail. No independent update endpoint is enabled in this preview; replace the Vantage Productivity suite through its distributor.

The vendored `imap-proto` 0.17.0 parser retains its own copyright and license texts in `vendor/imap-proto/LICENSE-MIT` and `vendor/imap-proto/LICENSE-APACHE`. Upstream's parser modification is documented in `vendor/imap-proto/PATCH.md`. Preserve these notices and all dependency license texts when redistributing a built companion. No upstream root NOTICE file is present in this pinned checkout.

Vantage Mail uses its own Google Desktop OAuth registration, the system browser, S256 PKCE, and an ephemeral loopback callback. Google account passwords are not collected by the client. `OAuthClient` debug output redacts client identifiers and secrets; refresh-token storage keeps the isolated Vantage keyring service. See `VANTAGE_GOOGLE_SIGN_IN.md` for registration and Testing-mode requirements.
