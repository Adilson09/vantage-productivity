# HTML crash-recovery copies

HTML recovery runs on its own thirty-second timer, including unnamed documents and when normal AutoSave is off. It writes a private shared recovery journal, never a normal document, and keeps the editor dirty. Manual Save and the existing named-document AutoSave remain separate. Recovery restores through the shared panel as a new HTML file; it never silently overwrites the original.

Each successful document activation owns a new UUID. A monotonic snapshot sequence is captured before the asynchronous preview request; a separate revision tracks source, inline visual, style-preview and panel input changes. Main validates the live owner, activation, revision and actual opened/saved path. Clean Save/undo acknowledgments fence only snapshots already started; new edits survive a slow save. Explicit discard invalidates the producer before awaiting storage and suppresses unchanged-content recreation until a fresh edit. A refused storage discard refuses the close/discard. A crashed or destroyed renderer leaves its committed entry intact.

Menu and MCP Save requests have sender/activation-bound UUIDs. Publishing bytes is separate from the final current-source acknowledgment, so a successful old write cannot authorize closing over new typing, pending styles or a replacement document. Unchanged clean files pass the renderer check and recovery cleanup without rewriting their bytes. Unattended MCP destinations belong only to their request and do not become the document path before publication. Timeout, destruction and activation replacement fail the old waiter; late acknowledgments cannot settle its replacement.

Same-path Reload retains its UUID and monotonic snapshot sequence. It performs an exact bounded UTF-8 read and pure validation, checks source/revision/path/pending controls and composition after every asynchronous preparation step, and replaces the model synchronously. The floor captures every already-allocated old snapshot, including those allocated during the read. Main advances a content-operation epoch, rejects old Save/clean receipts, checks snapshot floors before and after disk commit, and serializes cleanup behind old in-flight writes. Newer sequence snapshots survive cleanup. Read/validation/obsolete-source failure retains the current editor and recovery; cleanup failure has a separate visible warning and retains the previous good journal without replacing newer editor state.

Capture reads CodeMirror state and requests the inline editor's current text/rich HTML through a nonce-bound reply. It never blurs controls, dispatches editor transactions, commits overlays or clears drafts. Composition and active drags defer a snapshot. Pending text, image alt text and style previews are compiled against a private string. An unfinished CSS field is encoded with its stable element path in a recovery-only comment and reopened in the style panel; this preserves even text that is not yet a valid CSS declaration.

Local assets are closed over using parse5, CSS-tree, es-module-lexer and Acorn in a bounded worker thread. Images/srcset, CSS imports and URL references, fonts, SVG image references, media and accepted static data-only JavaScript module imports become embedded data URLs. No page script is executed and no remote URL is fetched. The output is independent of the original local asset directory for accepted documents. Remote declarative images, styles, fonts and media remain external; a marker and editor notice disclose the remaining network dependence.

Scripted pages have an explicit support boundary. A positive, bounded Acorn syntax-tree whitelist accepts const declarations containing primitive/array/plain-object/static-template data, references to established data bindings, and static local or embedded data-only imports/exports. Every imported module must satisfy the same rule. Calls, constructors, member/computed access, assignments, functions, control flow, spread, dynamic imports and import.meta are refused. Opaque remote executable scripts/imports, nonempty event handlers, executable javascript URLs, speculation rules and dynamic SVG animation/set elements are refused without fetching or executing them. Inert JSON/JSON-LD blocks remain document data. These refusals retain the previous good recovery entry and show an actionable warning; normal manual HTML Save still handles the authored page unchanged. Arbitrary scripted-page crash recovery is not claimed by this slice.

The existing preview asset allowlist is preserved. JSON, text, HTML and dotfile neighbours are not newly granted. Paths are bound to the document activation's real folder or an explicit file grant, with regular-file/symlink/realpath checks and bounded, identity-checked reads. Missing or ungranted media, unresolved temporary URLs, local import cycles, dynamic resource construction, unsupported SVG symbols/import maps/integrity/content policies, invalid UTF-8, quota/storage failures and oversized output fail visibly while retaining the previous good entry. Unsupported runtime-generated dependencies are not silently omitted. Recovery does not capture a page script's arbitrary JavaScript heap or unsaved network/server state. Existing HTML password protection support is unchanged; the shared optional operating-system-protected vault remains available.

Limits: 16 MiB complete HTML per entry, 256 local resource targets, dependency depth eight, 100,000 HTML nodes, 200,000 tokens per stylesheet/script, 200,000 nodes and depth 128 per accepted script syntax tree, 16 MiB aggregate source/raw local bytes, 32 MiB encoded cache, five seconds processing, 256 MiB old-generation worker heap plus 32 MiB young generation, 64 KiB diagnostics, two running workers and four queued captures. Queue waits expire rather than growing indefinitely, and timed-out workers keep their slot until actual exit. These are JavaScript heap, explicit allocation and job limits, not a hard operating-system process RSS ceiling. Worker threads share the Electron process, and native/runtime overhead also consumes memory. The shared journal also enforces its 128 MiB/64-entry limits and optional operating-system encryption.
